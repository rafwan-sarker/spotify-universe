    **src/shaders/star.vert.glsl** -- Billboard vertex shader per D-01, D-02, D-03, D-05:
    - Declare per-instance attributes: instanceColor (vec3), instanceSize (float), instanceBrightness (float), instanceBirthTime (float), instancePhaseOffset (float), instanceIsTopTrack (float)
    - Declare uniform: uTime (float)
    - Fade-in (D-05): `smoothstep(0.0, 1.5, uTime - instanceBirthTime)` -- stars grow from invisible to full size over 1.5 seconds
    - Twinkle (D-02): `1.0 + 0.12 * sin(uTime * 2.5 + instancePhaseOffset)` -- subtle brightness pulsing
    - Size pulse for top tracks (D-03): `1.0 + instanceIsTopTrack * 0.08 * sin(uTime * 1.8 + instancePhaseOffset * 0.7)`
    - Billboard technique: extract world position from instanceMatrix, convert to view space, offset by position.xy * finalScale
    - Pass vUv (from uv), vColor (from instanceColor), vAlpha (brightness * fadeIn * twinkle) to fragment shader
    - Use the exact shader pattern from RESEARCH.md Pattern 2 section

    **src/shaders/star.frag.glsl** -- Radial glow fragment shader per D-01, D-04:
    - Use vUv to compute distance from quad center (0.5, 0.5)
    - Discard fragments where distance > 0.5 (circular star from rectangular quad)
    - Radial glow: `smoothstep(0.5, 0.0, d)` for soft falloff
    - Core brightening: mix vColor with white at center (`smoothstep(0.25, 0.0, d)` mix factor * 0.6)
    - Final output: `vec4(color * alpha, alpha)` for correct additive blending
    - Use the exact shader pattern from RESEARCH.md "Fragment Shader (Radial Glow)" section

    **src/lib/galaxy-buffers.ts** -- Pure functions (no React/Three.js dependency for testable core):
    - `MAX_STARS = 12000` constant (pre-allocate for max capacity)
    - `createStarBuffers(maxStars: number)` returns object with named Float32Arrays: colors (maxStars*3), sizes, brightnesses, birthTimes, phaseOffsets, isTopTracks (all maxStars)
    - `updateStarBuffers(buffers, stars: StarData[], startIndex: number, currentTime: number, spreadDuration?: number)` writes per-instance data for indices startIndex through stars.length-1:
      - Color: look up star.genre in GENRE_COLORS, fall back to mystery color
      - Size: star.size directly
      - Brightness: star.brightness directly
      - BirthTime: currentTime + (batchOffset / batchSize) * spreadDuration (default 0.8s) -- stagger for D-06
      - PhaseOffset: deterministic from star ID hash (use simple string hash to avoid Math.random for testability). Hash: sum of charCodes modulo (2 * Math.PI)
      - IsTopTrack: 1.0 if star.brightness > 0.6, else 0.0
    - Export types: `StarBuffers` interface

    **IMPORTANT -- the store uses reset+add (not incremental append).** The buffer utility itself does NOT need to handle this -- it just writes a range. The RealGalaxy component (Plan 02) will handle the birth-time-by-ID tracking. This plan's updateStarBuffers is a pure "write these stars into these buffer indices" function.
