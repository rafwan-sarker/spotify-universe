Build the RealGalaxy renderer component and wire it into GalaxyScene.     Create RealGalaxy.tsx -- the core galaxy renderer consuming real user data from the Zustand store.

    **Component structure:**
    - "use client" directive at top
    - Import THREE from "three", useRef/useMemo/useEffect from "react", useFrame from "@react-three/fiber"
    - Import createStarBuffers, updateStarBuffers, MAX_STARS from "@/lib/galaxy-buffers"
    - Import useAppStore from "@/lib/store"
    - Import shader source strings from "@/shaders/star.vert.glsl" and "@/shaders/star.frag.glsl" (use ?raw import suffix for Vite: `import vertexShader from "@/shaders/star.vert.glsl?raw"`)
    - Note: Add GLSL raw import type declaration if needed. Check if a vite-env.d.ts or similar already declares `*.glsl` modules. If not, add a `src/shaders/glsl.d.ts` with `declare module "*.glsl?raw" { const value: string; export default value; }`

    **Module-scope allocations** (per DemoGalaxy pattern -- never allocate in render/useFrame):
    - `const tempObject = new THREE.Object3D()` for matrix computation
    - `const tempColor = new THREE.Color()` -- though not needed since buffer utility handles colors

    **Refs:**
    - `meshRef = useRef<THREE.InstancedMesh>(null)`
    - `materialRef = useRef<THREE.ShaderMaterial>(null)`
    - `starCountRef = useRef(0)` -- tracks current visible star count
    - `birthTimeMapRef = useRef(new Map<string, number>())` -- maps star.id to assigned birth time, persists across batch updates to solve PITFALL 5

    **Buffer setup (useMemo):**
    - `buffers = useMemo(() => createStarBuffers(MAX_STARS), [])`

    **Geometry setup (useEffect, runs once after mount):**
    - Get geometry from meshRef.current.geometry
    - Attach 6 InstancedBufferAttributes to the geometry:
      - `instanceColor`: new THREE.InstancedBufferAttribute(buffers.colors, 3)
      - `instanceSize`: new THREE.InstancedBufferAttribute(buffers.sizes, 1)
      - `instanceBrightness`: new THREE.InstancedBufferAttribute(buffers.brightnesses, 1)
      - `instanceBirthTime`: new THREE.InstancedBufferAttribute(buffers.birthTimes, 1)
      - `instancePhaseOffset`: new THREE.InstancedBufferAttribute(buffers.phaseOffsets, 1)
      - `instanceIsTopTrack`: new THREE.InstancedBufferAttribute(buffers.isTopTracks, 1)
    - Store refs to each attribute for later needsUpdate flagging

    **Store subscription (useEffect, runs once -- CRITICAL for performance per PITFALL 4):**
    - Do NOT use `useAppStore(s => s.stars)` hook -- this causes re-renders.
    - Instead, use imperative subscription: `useAppStore.subscribe((state) => state.stars.length, callback)`
    - In the callback:
      - `const stars = useAppStore.getState().stars`
      - If newLength === 0: galaxy was reset. Set mesh.count = 0, clear birthTimeMapRef, set starCountRef = 0. Return.
      - For each star in the new array, check if birthTimeMapRef has its ID:
        - If YES: star already existed. Keep its existing birth time.
        - If NO: star is new. Assign birth time = currentTime + stagger offset. Add to birthTimeMapRef.
      - Call updateStarBuffers(buffers, stars, 0, currentTime) for the full range (since store replaces all stars)
      - BUT override birthTimes from birthTimeMapRef (the utility function assigns fresh times, so after calling it, overwrite buffers.birthTimes[i] with birthTimeMapRef.get(star.id) for each star)
      - Actually, simpler approach: Don't use updateStarBuffers for birth times at all. Instead:
        1. Call updateStarBuffers(buffers, stars, 0, currentTime) to write colors, sizes, brightnesses, phaseOffsets, isTopTracks
        2. Then loop through stars and for each: if birthTimeMapRef has the ID, write that time; if not, compute staggered time and store in map
        3. This correctly handles the reset+add pattern where existing stars keep their birth time
      - Set tempObject position and matrix for each star (same pattern as DemoGalaxy)
      - Set mesh.count = stars.length
      - Flag all InstancedBufferAttributes .needsUpdate = true
      - Flag mesh.instanceMatrix.needsUpdate = true

    **Animation loop (useFrame):**
    - Only update: `materialRef.current.uniforms.uTime.value = clock.elapsedTime`
    - One float per frame -- all animation runs in the shader (per RESEARCH.md "Don't Hand-Roll")

    **JSX return:**
    ```tsx
    <instancedMesh ref={meshRef} args={[undefined, undefined, MAX_STARS]} frustumCulled={false}>
      <planeGeometry args={[1, 1]} />
      <shaderMaterial
        ref={materialRef}
        vertexShader={vertexShader}
        fragmentShader={fragmentShader}
        uniforms={{ uTime: { value: 0 } }}
        transparent={true}
        blending={THREE.AdditiveBlending}
        depthWrite={false}
        depthTest={true}
        side={THREE.DoubleSide}
        toneMapped={false}
      />
    </instancedMesh>
    ```

    **Key decisions per user decisions and research:**
    - Per D-01: glowing orbs via radial shader on billboard quads with additive blending
    - Per D-04: AdditiveBlending + depthWrite:false (per PITFALL 2)
    - Per D-05: fade+scale via shader birthTime (per RESEARCH Pattern 2)
    - Per D-06: staggered birth times within each batch for smooth stream (per RESEARCH Pattern 3)
    - Per PITFALL 1: pre-allocate MAX_STARS, control draw range via mesh.count
    - Per PITFALL 4: imperative store subscription, no React re-renders for star data
    - Per PITFALL 5: track birth times by star ID in Map to survive reset+add cycles
    - Per PITFALL 6: set needsUpdate=true on all modified attributes

    **Performance target:** Single draw call for all stars. Zero CPU animation cost (only uTime uniform update per frame). Per GLXY-01: 5000+ stars at 60fps.
