    1. Create `src/lib/spotify-scopes.ts` exporting the OAuth scopes constant:
    ```typescript
    export const SPOTIFY_SCOPES = [
      "user-read-email",
      "user-read-private",
      "user-library-read",
      "user-top-read",
    ].join(" ")
    ```
    Per Pitfall 4 from RESEARCH.md: request ALL needed scopes upfront in Phase 1. user-library-read and user-top-read are needed in Phase 2 but must be requested now to avoid re-authorization.

    2. Create `src/auth.ts` with Auth.js v5 configuration per RESEARCH.md Pattern 1:
    - Import NextAuth from "next-auth" and Spotify from "next-auth/providers/spotify"
    - Import SPOTIFY_SCOPES from "@/lib/spotify-scopes"
    - Configure Spotify provider with clientId, clientSecret from env vars, and authorization params with scope
    - Set session strategy to "jwt"
    - Set pages.error to "/auth/error" (per D-08)
    - Implement jwt callback with:
      a. Initial sign-in: persist access_token, refresh_token, expiresAt (account.expires_at * 1000)
      b. Token still valid check: Date.now() < expiresAt - 5 * 60 * 1000 (5-minute buffer per research)
      c. Token refresh: POST to https://accounts.spotify.com/api/token with Basic auth header and grant_type=refresh_token
      d. On refresh failure: set token.error = "RefreshTokenError" (per D-09)
      e. On refresh success: update accessToken, expiresAt, and conditionally update refreshToken if Spotify returns a new one
    - Implement session callback: pass user.id from token.sub, forward error field if "RefreshTokenError"
    - Export { handlers, auth, signIn, signOut }

    CRITICAL per Pitfall 1: The jwt callback must ONLY refresh when truly expired (with buffer). Multiple invocations per render must not each attempt a refresh.
