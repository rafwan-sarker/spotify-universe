# Phase 04 — UI Design Contract

> Visual and interaction contract for Navigation & Interaction. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom Tailwind + CSS variables) |
| Preset | not applicable |
| Component library | none (DOM layer is thin overlays on R3F Canvas) |
| Icon library | inline SVG (established pattern from Phase 1) |
| Font | system-ui, -apple-system, sans-serif (from globals.css) |

**Rationale:** This project is canvas-first with minimal DOM UI. The existing neon synthwave aesthetic uses CSS custom properties and Tailwind utilities. shadcn adds overhead without value for floating overlays on a fullscreen 3D canvas. Consistent with Phase 1 and Phase 3 patterns.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#000005` (`--bg-deep`) | Canvas background, full viewport |
| Secondary (30%) | `rgba(0, 0, 20, 0.85)` with `backdrop-filter: blur(8px)` | Info card background, search bar background, search dropdown background |
| Accent (10%) | `#00f0ff` (`--neon-cyan`) | See reserved-for list below |
| Destructive | not applicable | No destructive actions in this phase |

**Accent reserved for (exhaustive list):**
1. Info card border glow (`border: 1px solid rgba(0, 240, 255, 0.6)`)
2. "Open in Spotify" link text color
3. "Warp to Artist" button border and text
4. Search bar border when focused
5. Search result hover highlight
6. Keyboard shortcut badge background (`rgba(0, 240, 255, 0.15)`)

**Additional semantic colors (non-accent):**
- `white` at varying opacity for text hierarchy: `rgba(255, 255, 255, 1.0)` for track name, `rgba(255, 255, 255, 0.7)` for artist/metadata, `rgba(255, 255, 255, 0.4)` for hint text
- Warp streak particles: white-to-cyan gradient (`#ffffff` to `#00f0ff`) with additive blending (3D scene, not DOM)

**Source:** Existing CSS variables in `globals.css`, glow pattern from `ConnectSpotifyButton.tsx` and `ProfileMenu.tsx`.

## Component Inventory

### 1. Star Info Card (drei Html overlay in 3D space)

**Trigger:** Click a star (proximity-based picking per RESEARCH.md Pattern 3)
**Position:** Offset `[2, 1, 0]` from star position in world space, rendered via drei `Html` component with `distanceFactor={10}`
**Dismiss:** Click empty space or press Escape (per RESEARCH.md open question 1 recommendation)

**Layout:**
```
+---------------------------------------+
|  [Album Art 64x64]  Track Name (16px) |
|                     Artist Name (14px) |
|                     Genre Badge (12px) |
+---------------------------------------+
|  [Spotify Icon] Open in Spotify       |
|  [Warp Icon]    Warp to Artist        |
+---------------------------------------+
```

**Sizing:**
- Card width: 280px fixed
- Album art: 64px x 64px, rounded 8px corners
- Top section padding: 16px
- Button section padding: 8px vertical, 16px horizontal
- Divider between sections: `1px solid rgba(255, 255, 255, 0.1)`

**Styling:**
- Background: `rgba(0, 0, 20, 0.85)` with `backdrop-filter: blur(8px)`
- Border: `1px solid rgba(0, 240, 255, 0.6)`
- Box shadow: `0 0 10px rgba(0, 240, 255, 0.3), inset 0 0 10px rgba(0, 240, 255, 0.1)`
- Border radius: 12px
- Genre badge: pill shape, background `rgba(0, 240, 255, 0.15)`, text `#00f0ff`, 12px font, 4px vertical / 8px horizontal padding

**Animation:** Fade in with Motion `initial={{ opacity: 0, scale: 0.95 }}` to `animate={{ opacity: 1, scale: 1 }}` over 200ms ease-out

**Album art fallback:** When `albumArt` is undefined (demo mode stars), show a 64x64 square filled with the star's genre color at 30% opacity, with a music note icon (inline SVG, 24px, white at 50% opacity) centered.

**Source:** D-06, D-07, D-09 from CONTEXT.md; Pattern 5 from RESEARCH.md.

### 2. Search Bar (DOM overlay)

**Trigger:** Press `/` or `Cmd+K` (keyboard shortcut), or click a search icon if visible
**Position:** Top center of viewport, `fixed top-4 left-1/2 -translate-x-1/2 z-20`
**Dismiss:** Press Escape, click outside, or select a result

**Layout:**
```
+--------------------------------------------------+
|  [Search Icon]  Search songs or artists...  [/]  |
+--------------------------------------------------+
|  Result 1: Track Name - Artist Name              |
|  Result 2: Track Name - Artist Name              |
|  Result 3: Track Name - Artist Name              |
|  ...up to 8 results                              |
+--------------------------------------------------+
```

**Sizing:**
- Container width: 480px (max), responsive down to 320px on smaller viewports
- Input height: 44px (touch-target friendly)
- Input padding: 16px left (after icon), 16px right
- Search icon: 20px, `rgba(255, 255, 255, 0.4)`
- Keyboard shortcut badge: `[/]` or `[Cmd+K]`, 12px, right-aligned inside input
- Dropdown result item height: 44px
- Dropdown max visible results: 8

**Styling:**
- Input background: `rgba(0, 0, 20, 0.9)` with `backdrop-filter: blur(12px)`
- Input border: `1px solid rgba(255, 255, 255, 0.15)` default, `1px solid rgba(0, 240, 255, 0.6)` on focus
- Input border radius: 12px (top only when dropdown is open, full when closed)
- Input text: 16px, white, weight 400
- Placeholder text: `rgba(255, 255, 255, 0.4)`
- Dropdown background: `rgba(0, 0, 20, 0.95)` with `backdrop-filter: blur(12px)`
- Dropdown border: `1px solid rgba(255, 255, 255, 0.1)`, radius 0 0 12px 12px
- Result item: 14px track name white, 14px artist `rgba(255, 255, 255, 0.5)`, separated by ` - `
- Result hover: background `rgba(0, 240, 255, 0.08)`, left border `2px solid #00f0ff`
- Result active (keyboard selected): same as hover
- No results state: "No matching stars found" at 14px, `rgba(255, 255, 255, 0.4)`, centered, 44px height

**Animation:**
- Open: Motion `initial={{ opacity: 0, y: -8, scale: 0.98 }}` to `animate={{ opacity: 1, y: 0, scale: 1 }}`, 150ms ease-out
- Close: reverse, 100ms ease-in
- Dropdown appears with `initial={{ opacity: 0, y: -4 }}` staggered 50ms after input opens

**Input behavior:**
- Auto-focuses on open
- Debounce search: 100ms after typing stops (Fuse.js search is fast but debounce avoids unnecessary re-renders)
- Keyboard navigation: Arrow up/down to move through results, Enter to select, Escape to close
- Selecting a result triggers warp to that star (D-14)

**Source:** D-11, D-12, D-13, D-14 from CONTEXT.md; fuse.js setup from RESEARCH.md.

### 3. Warp Streaks (3D particle system, NOT DOM)

This is a 3D scene element, not a DOM component. Documented here for visual contract completeness.

**Trigger:** Any warp event (star click, search result selection, "Warp to Artist" button)
**Visual:** 500-1000 line particles radiating from screen center, white-to-cyan with additive blending

**Three-phase animation (D-16):**

| Phase | Duration | Streak stretch | FOV | Streak opacity |
|-------|----------|---------------|-----|----------------|
| Acceleration | 0.3s (progress 0-0.25) | 0 to 3 | 60 to 80 | 0 to 0.8 |
| Full hyperspace | 0.5s (progress 0.25-0.67) | 3 to 5 | 80 | 0.8 |
| Deceleration | 0.4s (progress 0.67-1.0) | 5 to 0 | 80 to 60 | 0.8 to 0 |

**Color:** Start white (`#ffffff`), gradient to cyan (`#00f0ff`) along streak length. Alpha fades toward tail.
**Blending:** Additive (`THREE.AdditiveBlending`), consistent with star material.

**Source:** D-15, D-16, D-17, D-18 from CONTEXT.md; Pattern 4 from RESEARCH.md.

### 4. Flight Controls HUD Hint (transient DOM overlay)

**Purpose:** Show WASD/mouse control hints on first load, fade after 5 seconds or on first input.
**Position:** Bottom center, `fixed bottom-8 left-1/2 -translate-x-1/2 z-10`

**Layout:**
```
+----------------------------------------------+
|  WASD to fly  |  Right-drag to look  |  Scroll to boost  |
+----------------------------------------------+
```

**Sizing:**
- Height: auto
- Padding: 8px 16px
- Text: 12px, `rgba(255, 255, 255, 0.5)`, weight 400
- Separator: `|` character with 8px horizontal margin

**Styling:**
- Background: `rgba(0, 0, 20, 0.6)` with `backdrop-filter: blur(4px)`
- Border: `1px solid rgba(255, 255, 255, 0.08)`
- Border radius: 8px

**Animation:**
- Fade in on mount: 600ms ease-out
- Auto-dismiss after 5 seconds OR on first keyboard/mouse input: fade out 400ms

**Source:** Not explicitly in CONTEXT.md decisions but standard UX for custom 3D controls. Follows established DemoBanner animation pattern.

## Interaction Contracts

### Flight Controls (NAV-01)

| Input | Action | Behavior |
|-------|--------|----------|
| W / ArrowUp | Move forward | Camera moves along forward vector at cruise speed |
| S / ArrowDown | Move backward | Camera moves along negative forward vector |
| A / ArrowLeft | Strafe left | Camera moves along negative right vector |
| D / ArrowRight | Strafe right | Camera moves along right vector |
| Right-click + drag | Look around | Yaw (horizontal) and pitch (vertical, clamped -85 to +85 degrees) |
| Scroll wheel up | Speed boost | Increase speed multiplier |
| Scroll wheel down | Brake | Decrease speed multiplier |
| Key release | Drift | Decelerate over 1-2 seconds, zero-gravity coasting |
| No input for 5s | Auto-drift | Gentle camera rotation resumes, stops on any input |

**Mouse look rationale:** Right-click drag (not always-on) preserves left-click for star picking and DOM overlay interaction. Per RESEARCH.md Pitfall 3, pointer lock is NOT used.

**Source:** D-01 through D-05 from CONTEXT.md; Pattern 1 and Pitfall 3/5 from RESEARCH.md.

### Star Click (NAV-03)

| Step | What happens |
|------|-------------|
| 1 | User left-clicks on or near a star |
| 2 | Proximity-based picking finds nearest star within 30px screen distance |
| 3 | If star found: camera mode transitions to WARPING, target = star position |
| 4 | Warp streak effect plays (3 phases, 1.2s total) |
| 5 | Camera arrives near star, mode transitions to INSPECTING |
| 6 | Info card fades in beside the star (200ms) |
| 7 | Click empty space or press Escape: info card dismisses, mode returns to CRUISING |
| 8 | If no star found (click on empty space while no card open): nothing happens |

**Source:** D-06 through D-10 from CONTEXT.md; Pattern 3 from RESEARCH.md.

### Search Flow (NAV-04)

| Step | What happens |
|------|-------------|
| 1 | User presses `/` or `Cmd+K` |
| 2 | Search bar opens with animation, input auto-focuses |
| 3 | User types query, results appear after 100ms debounce |
| 4 | Arrow keys navigate results, Enter selects, Escape closes |
| 5 | Selection: search bar closes, camera warps to selected star |
| 6 | Info card opens on arrival at the star |

**Source:** D-11 through D-14 from CONTEXT.md.

### Warp Flow (NAV-02)

| Trigger | Warp target |
|---------|-------------|
| Click a star | Star's world position |
| Select search result | Star's world position |
| "Warp to Artist" button | Computed centroid of all stars by that artist |

All triggers use the same warp effect (D-17). Camera position always starts from current position (critical for mid-warp interrupts per RESEARCH.md Pitfall 2).

### Camera State Machine

```
IDLE         -> [any input]     -> CRUISING
IDLE         -> [warp trigger]  -> WARPING
CRUISING     -> [5s no input]   -> IDLE
CRUISING     -> [warp trigger]  -> WARPING
WARPING      -> [arrival]       -> INSPECTING
WARPING      -> [new warp]      -> WARPING (reset progress, new target)
INSPECTING   -> [movement key]  -> CRUISING
INSPECTING   -> [warp trigger]  -> WARPING
INSPECTING   -> [Esc / click empty] -> CRUISING (dismiss info card)
```

**Source:** Pattern 1 from RESEARCH.md, Pitfall 2 for interruption handling.

## Accessibility Notes

- Search bar: input has `role="combobox"`, `aria-expanded`, `aria-activedescendant` for dropdown navigation
- Search results: `role="listbox"` with `role="option"` items
- Info card: `role="dialog"`, `aria-label="Track information"`, focus trap not needed (Escape dismisses)
- Keyboard shortcut `/` is suppressed when any other input is focused
- All interactive elements reachable via keyboard (Tab, Enter, Escape)
- Controls hint text provides discoverability for keyboard-only users
- Color contrast: white text on dark glassy backgrounds exceeds 4.5:1 ratio
- Warp streaks: no flash/strobe concern (smooth gradient, not pulsing)
